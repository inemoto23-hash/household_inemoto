# プラン: 20260815_01 — 買い物メモとカレンダー下部の折り畳み化

## 対象機能・課題

カレンダーの選択日の下には現在「明細記録（その日の一覧）」と「予定」の2ブロックが縦に並んでいる。
ここへ **買い物メモ**（日付ごとの ToDo リスト。項目とチェックのみ）を **予定の下**に足す。

さらに、今後 `90_DOCUMENT/10_計画/03_機能候補.md` #10 の「今日は何の日」「現在位置の天気予報」が
同じ場所に並ぶ予定で、**素直に積むと選択日から下が延々と伸び、カレンダーを触るのにスクロールが要る**。
そこで、買い物メモの追加と同時に **3ブロックすべてを折り畳み式**にし、以後の機能も同じ器に載る形にする。

買い物メモの設計方針は `03_機能候補.md` §6（2026-08-13 ユーザー合意）に既にある。
本計画はその **第1段（入れ物だけ）** を作る。繰り越しと「この買い物を記帳」の橋は今回入れない。

## 決定事項（2026-08-15 Q&A）

| 論点 | 決定 |
|---|---|
| 項目の追加 | **インライン入力＋Enter**。シートは開かない |
| 折り畳みの既定 | 初回は「明細記録＝開く／予定・買い物メモ＝中身があれば開く」。以後は**端末に記憶**（localStorage） |
| カレンダーのマス目の印 | **出さない**。青丸は予定、赤丸は祝日のまま |
| 未チェックの繰り越し | **今回は入れない** |

## 実装方針

### L3: DB — 新しいテーブル（`schedules` は拡張しない）

`20_DATABASE/migrations/018_shopping.sql`（新規・冪等）。

```
dbo.shopping_items
  id / household_id / planned_on(DATE) / name(NVARCHAR 120)
  is_checked(BIT) / created_by / created_at / updated_at
索引 ix_shop_date (household_id, planned_on) INCLUDE (name, is_checked)
```

- **`schedules` を拡張しない。** 予定は時刻・通知予約・宛先・`schedule_reminders` への FK を持つ。
  買い物メモにはどれも要らず、拡張すると「通知の無い予定」という第2の形が `reminderSweep` や
  一覧の並び替えに混ざり込む。日付にぶら下がる点が同じだけで、性質が違う
- **論理削除にしない。** `schedules` が `is_deleted` を持つのは通知予約が FK で指しているため。
  買い物メモは何も指されない使い捨てのメモなので、物理 DELETE でよい
- 並びは **id 昇順（追加順）で固定**。チェックしても位置を動かさない。押した項目が
  目の前で飛ぶと、続けて押すときに1つ下を押してしまう
- `20_DATABASE/migrations/017_places.sql` が**まだ未適用**（`19_ユーザー作業.md` §6）。
  018 は 017 の後に流すこと

### BE — `shopping.ts` ＋ 純粋部分の隔離

- `11_BE_DEPLOYMENT/src/domain/shopping.ts` — zod スキーマのみ（`domain/schedule.ts` と同じ置き方）
- `11_BE_DEPLOYMENT/src/functions/shopping.ts` — `functions/schedules.ts` を型として踏襲
  （`withAuth` / `ok` / `fail` / `internalError` / `num` / `numOrNull` を再利用）

| メソッド | ルート | 中身 |
|---|---|---|
| GET | `shopping?from=&to=` | 期間で引く。`schedulesList` と同じ日付検証 |
| POST | `shopping` | `{ plannedOn, name }` |
| PATCH | `shopping/{id}` | `{ isChecked }` のみ。名前は直さない（消して足し直す） |
| DELETE | `shopping/{id}` | 物理削除 |

- 世帯チェックは全操作で `household_id = @hid` を WHERE に入れる（`schedulesUpdate` と同じ）
- トランザクションは要らない。1文で完結し、対で書く相手がいない
- `test/shopping.test.ts` — 入力検証（空文字・前後空白の trim・120字超・日付形式・`isChecked`）

### FE — 折り畳みの器を1つ作り、3ブロックで共有する

**新規 `10_SITE_DEPLOYMENT/src/components/Collapsible.tsx`**

- 見出し行は `<button aria-expanded>`（開閉）＋ その外に `action`。
  **`action` を開閉ボタンの中に入れない**（ボタンの入れ子は作れない）。
  `components/ui.tsx` の `SectionHeader` は残し、折り畳まない場所では今まで通り使う
- **中身は開いているときだけ描く。** 閉じているブロックの `useQuery` を走らせない
- 閉じていても中身の有無が分かるよう、見出しに **件数のチップ**を出す
  （買い物メモは `1/3` のようにチェック済み/全件）。件数は各ブロックが渡す。
  そのため `useQuery` は各ブロックが持ち、`Collapsible` はその中で**本体だけ**を包む形にする
- 開閉は `localStorage['kf.collapse.<storageKey>']` に記憶する。
  **保存値があれば常にそれを優先。** 無いあいだだけ「件数が 0 より大きくなったら1度だけ開く」
  （＝初回の既定）。利用者が一度でも触ったらその意思が勝つ
- ストレージが使えない環境（プライベートモード等）で落とさない。読み書きは try/catch で包み、
  失敗したら既定の開閉のまま動かす

**新規 `10_SITE_DEPLOYMENT/src/features/shopping/ShoppingBlock.tsx`**

- `features/schedule/ScheduleBlock.tsx` と同じ構え（`useQuery` ＋ 3つの `useMutation`）
- 一覧の下に **常設の1行入力**。Enter または ＋ で追加し、入力欄は即空にして続けて打てるようにする。
  空文字と空白だけは弾く
- 行は「チェックの丸 ／ 品名 ／ 🗑」。行そのものを押してもチェックが切り替わる。
  チェック済みは打ち消し線＋薄字にして、**その場に残す**
- **チェックの切り替えだけ楽観的更新**にする（`onMutate` で即塗り、失敗したら戻す）。
  レジ前で連打する操作なので、1件ずつ往復を待たせない。追加・削除は成功後に invalidate でよい
- カレンダーの月集計は買い物メモを数えないので、`['calendar']` の invalidate は不要

**`CalendarPage.tsx`**

- 選択日の一覧セクションを `Collapsible`（`storageKey="cal.entries"`、既定は開く、
  タイトルは `dayLabel(selectedDate)`、件数チップ付き）で包む
- `<ScheduleBlock>` の下に `<ShoppingBlock dateKey={selectedDate} />` を置く
- 記録シート・編集シートは折り畳みの外のまま（開閉と無関係に開ける）

**`ScheduleBlock.tsx`** — 外枠を `SectionHeader` から `Collapsible`（`storageKey="cal.schedule"`）へ差し替える。
中身・通知・シートには触らない。

**`lib/types.ts`** — `ShoppingItem` を追加。
**`styles/tokens.css`** — `.collapse-head` / `.collapse-toggle` / `.collapse-caret`（開くと回る）/
`.memo-row` / `.memo-check` を追加。既存の `.tx-row`（min-height 56px）は明細用に重いので流用しない。
