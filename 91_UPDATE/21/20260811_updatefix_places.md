# 20260811 アップデート完了記録（口座移動・位置情報・残高表示・店名候補）

## 1. 口座移動

口座タブに「⇄ 口座移動」を追加。

**予算の「組み換え」とは別物なので名前を分ける。** 組み換えは架空の枠を動かすだけだが、
口座移動は実際のお金が口座から口座へ移る。混同すると何が起きたか分からなくなる。

- 実体は `entries` の `kind = 'transfer'`。専用の台帳は作らない
- 確定前に変更前後を表示
- 移動先がクレジットなら引き落としとして扱われ、支払予定が減る旨を明示

## 2. 起動時の画面

**原因**: MSAL の `navigateToLoginRequestUrl: true`。
サインインを始めた画面へ戻る設定のため、設定画面からサインインすると設定画面に戻っていた。

`false` にして、起動時は必ず `redirectUri`（オリジン）→ `/` → カレンダーになるようにした。

## 3. 位置情報を通常の記録にも

`entryInputSchema` に `lat` / `lng` / `locationAccuracy` / `placeName` を追加し、
`entriesCreate` が `entries` へ保存するようにした。

**入力シートを開いているあいだだけ**取得する。常時追跡はしない。

クイック登録から確定する経路は、記録した時点の位置をそのまま `entries` へ引き継ぐ（実装済み）。
確定画面の店名候補も、現在地ではなく**記録した時点の位置**を使う。

## 4. 選択欄に残高を出す

| 欄 | 表示 |
|---|---|
| 財布・カード | `三井住友銀行（残 ¥250,000）` / `楽天カード（支払 ¥50,000）` |
| 支出カテゴリ | `食費（残 ¥18,300）` — 今月の残り |
| 収入カテゴリ | `給与（実績 ¥410,000）` |

カテゴリの残りは `bootstrap` に今月分の配分・消化を足して返す（往復は増やさない）。

**「今月」は日本時間で判定する。** サーバーは UTC で動くため、
`AT TIME ZONE 'Tokyo Standard Time'` を通さないと夜間に月をまたいだとき1日ずれた月を今月として扱う。

## 5. 現在地からの店名候補

`GET /api/places/nearby?lat=&lng=&spread=` を追加。

**外部の地図サービスは使わない。** その場所で過去に自分たちが入力した店名を返すだけ。
追加のリソースも料金も要らず、出てくる名前も普段使っている呼び方になる。

- 半径は既定で約150m（`NEARBY_DEGREES = 0.0015`）。`spread` で最大6倍まで拡大
- 回数の多い順、同数なら直近
- 選ぶと店名が入り、**空欄のカテゴリと財布も前回の内容で埋める**
- 候補が無ければ「この辺りでの記録はまだありません」と伝えて手入力へ促す
