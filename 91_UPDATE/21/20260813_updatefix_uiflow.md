## 追記: 支出カテゴリの行が1行だったり2行だったりした

### 原因

行は `[色] [名前] [使用額/母数] [残り]` の4つを `flexWrap: 'wrap'` で並べていた。
そのため**名前の長さと「調整」の有無で折り返す位置が変わり**、
行の高さが揃わなかった。折り返しは入る/入らないで決まるので、
1件ずつ違う結果になる。

### 直し方

口座の行と同じ組み方にした。**折り返さない。**

```
[色] 食費                          ¥7,660  ›
     52,340 / 60,000
[============ バー ============]
```

- 名前と内訳を縦に積み、残りを右に置く
- 入りきらないときは**名前が縮む**（省略記号）
- **内訳も1行に固定した。** 折り返させると、繰越や調整が付いた行だけ背が高くなる。
  入りきらないときは末尾（繰越・調整）から欠けるが、主役の「使った / 母数」は必ず残る

### 確認

Playwright で 320 / 360 / 390px の3幅を測った。長い名前・大きな金額・繰越・調整を
混ぜた5行で、**すべての幅で全行 69px に揃う**ことを確認。
内訳を1行に固定する前は 320px で 1行だけ 85px になっていた。

プールの行も同じ作り（`flexWrap` + `flex: 1 1 160px`）だったので併せて直した。
収入の行とカテゴリ名は、長いときに押し出さないよう省略するようにした。

### 併せて直した名前の衝突

操作タイルに付けた `.tile` が、**口座のアイコン・アイコン選択・設定などが使っている
既存クラスと同名**だった。CSS は後から書いたほうが勝つので、どちらかが必ず崩れる。
`.action-tile` / `.action-grid` に分けた。

**同じファイルの中で名前が衝突していることに、追加時に気付けなかった。**
既存のクラス名を確認せずに増やしたのが原因。

## 追記3: 店名を直しても分析に反映されなかった

### 症状

履歴から店名を「ガソリン」→「ENEOS」に直したのに、分析では「ガソリン」のまま。

### 原因

**`place_id` が古いマスタを指したままだった。**

```
id=38  merchant='ENEOS'  座標なし  place_id=12 → マスタ名 'ガソリン'
```

`entriesUpdate` は店名を直すと `attachPlace` で引き直していたが、
**見つからなかったときに何も書かずに戻っていた**。

「ENEOS」という名前のマスタは無く、この記録は座標も持たない。
座標なしのマスタは新しく作らない方針なので、引き直しは「該当なし」になる。
そこで書かずに戻ったため、古い `place_id` が残った。
分析は `COALESCE(マスタの表示名, merchant, place_name)` で束ねるので、マスタ名が勝つ。

**座標を持つ記録では起きない**（新しいマスタが作られて置き換わる）。
座標を持つマスタは 45件中3件しかないため、実際にはほぼ全ての記録がこの経路に入る。

### 直し方

`attachPlace` に `clearIfUnmatched` を足し、**店名が変わったときは NULL を書く**。
紐付けが外れれば、分析は `merchant` に落ちて「ENEOS」と出る。

**名前が変わったときだけ引き直す。** 変わっていないのに引き直すと、
同名のマスタが複数ある状態で「決められない」と判定され、黙って紐付けが外れる。

### 既存データ

食い違っていた記録を洗い出して直した（1件）。
新しい名前のマスタがあればそちらへ、無ければ外す。

```
食い違っている記録: 1件  →  直した: 1件
id=38  merchant='ENEOS'  place_id=null  分析での表示='ENEOS'
```

**どの記録からも指されなくなったマスタが1件（「ガソリン」）残っている。**
消していない。害は無いが、マスタの編集画面ができたら整理できるようにする。

## 追記6: カレンダーが枠から飛び出していた

### 症状

スマホでカレンダーの**土曜の列がカードの外へ出ていた**。

### 原因

```css
.cal-grid { grid-template-columns: repeat(7, 1fr); }
```

**`1fr` は `minmax(auto, 1fr)` の略で、中身の最小幅より縮まない。**
金額の桁が多い日があるとその列が広がり、7列ぶんが枠を押し広げる。

セルの最小幅は「その日の金額の文字幅＋余白」で決まるので、
**6桁の支出がある月だけ崩れる**という気付きにくい壊れ方をしていた。

### 直し方

`minmax(0, 1fr)` にする。0 を下限にすれば、狭い画面ではセルが縮んで
中の文字が切れるだけで済む。あわせてセルに `min-width: 0` と `overflow: hidden`、
金額に省略記号を付けた。

### 実測（1週目の土曜が、カードの内側からはみ出す量）

| 幅 | 修正前 | 修正後 |
|---|---|---|
| 320px | **58px**（ページに横スクロールも発生） | 0px |
| 360px | **18px** | 0px |
| 390px 以上 | 0px | 0px |

### 併せて直した「数字が縦に切れる」

支出と収入の**両方がある日**で、金額が2行になってセルからはみ出していた。

狭い端末ではセルが 40px 角ほどしかなく、`.cal-day`(18px) と2行の金額(25px)は
**物理的に入らない**。切れた数字を見せるより支出だけを確実に読ませるほうが良いので、
400px 未満では**2行目を出さない**ことにした。収入はその日を開けば見える。

広い画面（400px 以上）では今までどおり2行とも出る。

**収入額がカレンダー上で見えなくなる。** 気になるようなら、
収入がある日に小さな点を出す形にもできる。

## 追記7: 閾値が保守的すぎて、出るべきものが隠れていた

追記6 で入れた `max-width: 400px` の指定が2つとも効きすぎ、

### 測ってから決め直した

| 何を隠すか | 本当に必要な幅 | 直した閾値 |

| ブランド名 | ブランド＋月ナビで **291px**。340px あれば収まる | **339px 以下**だけ隠す |

**400px は何の根拠も無い数字だった。** 崩れを止めることだけを見て、
「どこから必要なのか」を測っていなかった。

### 収入の行を入れるためにセルを詰めた

そのままでは 375px でも入らなかったので、内側を詰めた。

| | 前 | 後 |
|---|---|---|
| 日付 | 12px / 高さ18px | 11.5px / 高さ15px |
| 金額 | 10px / 行間1.25 | 9px / 行間1.15 |
| セルの余白 | 4px 4px 3px | 3px 4px 2px |

**セルは正方形（`aspect-ratio: 1/1`）なので、高さは幅から決まる。**
入るかどうかは端末の幅で決まり、こちらで高さを増やすとカレンダー全体が縦に伸びる。
縦を増やさずに収める道を選んだ。

### 実測（320 / 340 / 360 / 375 / 390 / 412 / 430px）

| 幅 | KakeiFlow | 収入の行 | 数字の切れ | はみ出し |
|---|---|---|---|---|
| 320px | 隠れる | 隠れる | 0件 | 0px |
| 340 / 360px | **出る** | 隠れる | 0件 | 0px |
| 375px 以上 | **出る** | **出る** | 0件 | 0px |
