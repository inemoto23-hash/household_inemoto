# 20260810 アップデート予定

- **計画書**: [91_UPDATE/01/20260810_rebuild_plan.md](../01/20260810_rebuild_plan.md)
- **区分**: Phase 0 の追加対応（世帯メンバー管理）

## 背景

オーナーが世帯メンバーを追加する際、`users` テーブルへの登録を手作業（SQL 直接実行）で行う必要があった。
Entra のゲスト招待は手動のままでよいが、**`users` への登録は管理画面から完結**させたい。

あわせて、入力時の既定財布と小遣いカテゴリの持ち方を見直す。

## 決定事項

| 論点 | 決定 |
|---|---|
| Entra ゲスト招待 | **手動のまま**。MI に `User.Invite.All` は付与しない |
| 財布の所有者 | `accounts.owner_user_id` は任意のまま据え置き。代わりに **`users.default_account_id`** を追加 |
| 小遣いカテゴリ | **人別に分ける**（`小遣いたけ` / `小遣いささ`） |

## 実施内容

### 1. DB マイグレーション（`20_DATABASE/migrations/002_user_invite.sql`）

- `users.provider_user_id` を **NULL 許容**へ変更（招待済み・未サインイン状態を表現するため）
  - 既存の `UNIQUE` 制約は NULL を1行しか許さないため、**フィルタ付き一意インデックスへ置換**する
- `users.default_account_id` を追加（`accounts` への FK、NULL 許容）
- `users.invited_at` / `invited_by` を追加（招待の記録）
- 予算カテゴリ `小遣い` を `小遣いたけ` へ改称し、`小遣いささ` を追加
  - 取引が0件のため安全に実施できる。繰越ポリシーは両方 `full` を維持

### 2. バックエンド

- **初回サインイン時の自動紐付け**
  `oid` で見つからない場合、トークンのメールアドレスで招待済み行（`provider_user_id IS NULL`）を検索し、
  見つかれば `oid` を書き込んで確定する
- **メンバー管理 API**（オーナーのみ実行可）
  - `GET    /api/members` 一覧
  - `POST   /api/members` 追加（メール + 表示名）
  - `PATCH  /api/members/{id}` 表示名・色・既定財布・権限の更新
  - `DELETE /api/members/{id}` 無効化（論理削除。実データは残す）
- 自分自身の設定更新 `PATCH /api/me`（表示名・既定財布）

### 3. フロントエンド

- `/settings/members` ルートを追加
- メンバー一覧（サインイン済み / 招待中の別を表示）
- 追加フォーム（メール + 表示名）
- 追加後に **Entra 側の招待手順を画面上で案内**する（手動作業が残るため）

## ユーザー手動手順

メンバー追加時、**Entra 管理センターでのゲスト招待は引き続き手動**で必要。
手順は [90_DOCUMENT/10_計画/19_ユーザー作業.md](../../90_DOCUMENT/10_計画/19_ユーザー作業.md) §2 を参照。
画面上にも同じ案内を表示する。

## 想定リスク

| リスク | 対策 |
|---|---|
| `provider_user_id` の UNIQUE 制約を外す際、重複が入り込む | フィルタ付き一意インデックスで NULL 以外の重複は引き続き禁止 |
| メールアドレス照合でなりすまし | Entra が検証済みのクレーム（`preferred_username` / `email`）のみ使用し、リクエスト本文の値は使わない |
| オーナーが自分を無効化して詰む | 最後の `owner` は無効化できないようサーバー側で拒否 |
