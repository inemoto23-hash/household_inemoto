## 1. 買い物メモを追加した

カレンダーの選択日にぶら下がる ToDo リスト。**品名とチェックだけ**を持つ。
`entries` とは接続しないので、残高にも予算にも分析にも一切影響しない。

追加は一覧の直下に**常設した1行の入力欄**で、打って Enter（または ＋）。
入力欄は応答を待たずに空にするので、続けて何件でも打てる。
日本語の変換中の Enter は拾わない（変換確定が追加になってしまう）。

行を押すとチェックが切り替わる。**いちばんよく使う操作を、いちばん大きな面**に割り当てた。
✕ で消す。品名の編集は持たせていない（打ち間違いは消して足し直すほうが速く、
編集の導線を足すと「行を押す＝チェック」と取り合いになる）。

### 決めたこと

- **`schedules` を拡張せず、`shopping_items` を新しく作った。**
  予定は時刻・通知の宛先を持ち、`schedule_reminders` から FK で指されている。
  買い物メモにはどれも要らず、混ぜると「通知の無い予定」という第2の形が
  `reminderSweep` と一覧の並び替えに入り込む。日付にぶら下がる点が同じなだけで性質が違う
- **論理削除にしない（物理 DELETE）。** 何からも指されない使い捨てのメモなので、
  `is_deleted` を持つ理由が無い
- **並びは追加順で固定。チェックしても動かさない。** 済んだものを下へ送ると、
  押した項目が目の前で飛び、続けて押すときに1つ下を押してしまう。
  打ち消し線と薄字でその場に残す
- **チェックだけ楽観的更新にした。** レジの前で続けて押す操作なので、1件ずつ往復を待たせない。
  失敗したら元に戻し、理由を出す。追加・削除は応答後に取り直すだけでよい
- 品名の検証は `domain/shopping.ts`（zod）と DB の `ck_shop_name` の両方で行う。
  **画面の作りには依存させない**という既存の流儀に合わせた
- カレンダーのマス目に印は増やしていない。青丸は予定、赤丸は祝日のまま

## 2. カレンダー下部の3ブロックを折り畳めるようにした

明細記録・予定・買い物メモが縦に積まれ、今後さらに「今日は何の日」「天気」が続く。
素直に積むと選択日から下が延々と伸び、**カレンダーを触るのにスクロールが要る**。

`components/Collapsible.tsx` を1つ作り、3ブロックで共有する。

- **閉じているブロックは中身を描かない。** 問い合わせ（`useQuery`）も走らない。
  代わりに見出しへ件数のチップを出すので、閉じていても中身の有無は分かる
  （買い物メモは `1/3` のようにチェック済み/全件）
- そのため問い合わせは各ブロックが持ち、`Collapsible` は本体だけを包む形にした
- 見出し全体が開閉ボタン。**操作ボタン（＋ 予定）はその外**に置く
  （ボタンの入れ子は作れない。`Field` と `FieldGroup` を分けているのと同じ理由）
- **シートは折り畳みの外**に出した。畳んだ拍子に編集中の入力が消えない
- 開閉は `localStorage['kf.collapse.<キー>']` に覚える。**保存値があれば常にそれを優先**し、
  無いあいだだけ「件数が 0 より大きければ開く」を効かせる。一度でも触れば利用者の意思が勝つ
- localStorage は使えないことがある（プライベートモード・容量超過）。
  読み書きは try/catch で包み、**覚えられなくても開閉そのものは動く**

既定は 明細記録＝開く、予定・買い物メモ＝中身があれば開く。

## デプロイ（2026-08-15 実施）

**マイグレーション → BE → FE の順で流した。** BE より先に FE を出すと、
まだ買い物メモを持たない BE に対して画面だけが出る。

| # | 対象 | 結果 |
|---|---|---|
| 1 | `018_shopping.sql` | 適用（上記） |
| 2 | BE `func azure functionapp publish` | 成功。`shoppingList` / `Create` / `Update` / `Delete` の4本が登録された |
| 3 | FE `KakeiFlow_GH` の `main` へ push（`fbbf46d`） | SWA が自動ビルド。約80秒で新バンドル配信 |

デプロイ後の疎通:

- `GET /api/health` → **200**
- `GET /api/shopping?from=&to=`（認証なし） → **401**。404 ではないのでルートは登録されている
- SWA が配信する JS が `index-C3NWSbCO.js` に変わり、ローカルビルドと同じハッシュになった

適用後に確かめること:

- 品名を3件足す → 再読込しても残る
- チェックを連打 → 即座に塗り変わり、リロード後も一致する
- ✕ で消える。別の日を選ぶと空になる（日付にぶら下がっている）
- 3ブロックを開閉 → リロード後も同じ形。別の日付・別の月へ移っても保たれる
- 予定の通知・明細の追加編集がこれまで通り動く
