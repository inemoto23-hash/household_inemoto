# 20260812 アップデート予定（支出マップの番号ずれと代表座標）

- **計画書**: `91_UPDATE/01/20260812_05_plan.md`（承認済み）
- **ユーザー手動手順**: **BE の手動デプロイ**（`cd 11_BE_DEPLOYMENT && npm run deploy`）。
  DB マイグレーションは不要

## やること

一覧の番号と画像のピン番号が食い違い、①のピンが別の店の場所に立っていた。

| 対象 | 内容 |
|---|---|
| DB | 変更なし |
| BE | `shared/places.ts`(新)、`functions/analytics.ts`、`functions/map.ts`、`functions/locations.ts` |
| FE | `features/settings/HomePage.tsx`、必要なら `lib/types.ts` |
| 文書 | `system_flow.md` / `91_UPDATE/21/` |

## 原因

**場所の集計が2か所に書かれており、順位に使う金額が別物だった。**

- 地図（`map.ts`）: `WHERE e.lat IS NOT NULL` を集計の**前**に置いていたため、
  座標つきの記録だけの合計で並べていた
- 一覧（`analytics.ts`）: 座標の有無を見ず、全記録の合計で並べていた

座標を持たない記録が増えるほどずれる。そして**増やしたのは我々**——
一括登録（位置を受け取らない）・自宅（座標を落とす）・`dropIfImprecise`（誤差500m超を捨てる）。

## 決めたこと

- 場所集計は `shared/places.ts` に**1本だけ**置く。地図と一覧は同じものを読む
- **番号は「座標つきに絞ってから数える」の1回だけ。** 地図側の `TOP 10` は廃止し、
  一覧と同じ 30 件を同じ順で受けてから絞る
- 代表座標は `AVG` をやめ、**直近の座標つき記録**の座標にする（窓関数 `ROW_NUMBER`）
- 代表座標は**同じ月の中から**選ぶ。全期間に広げると「位置つきが1件も無い月は 204」の
  約束が変わり、機能の意味が変わってしまう
- `locationsClear` に `includeUnknown` を足し、**明示したときだけ**精度不明も消す

## 注意する点

- **原則は既に `system_flow.md` に書いてある**（「地図と一覧の番号は揃える」）。
  文言を足すのではなく、**ずれられない作り**にすることが今回の主旨。
  place の SELECT が `map.ts` / `analytics.ts` に残っていないことを必ず確認する
- **`OUTER APPLY` で店ごとに引き直さない。** Basic 5DTU では索引探索が30回積む。
  窓関数なら月内の行を1回なめるだけで済む
- **`rn = 1` が座標なしの行になる場合がある**（その店に座標つきが1件も無いとき）。
  そのとき `lat` は NULL のままになり、地図に出ない。これが望む挙動
- **精度不明の消去は既定で行わない。** 値が無いことは「悪い」ことの証拠にならない。
  画面でも別のボタンにして、まとめて押せないようにする
- 座標は復元できない。消す前に件数を見せる（`summary` の `unknownAccuracy` を使う）

## 今回やらないこと

- **店名マスタ（座標つき）** — 別途検討。代表座標の根治と同名別店舗の区別はそちらの筋
- AI による店名の名寄せ — 同上
- 代表座標を全期間から選ぶ案 — 204 の約束が変わるため、マスタと合わせて考える
- 同名の別店舗を2つのピンに分けること
