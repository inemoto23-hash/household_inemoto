# 予算からの明細表示・明細の編集導線・位置情報のリセットと PC 対策

## Context

4つの要望をまとめて扱う。前半2つは「明細をどこから見て、どこから直せるか」、
後半2つは「PC で入った出鱈目な座標」の後始末と再発防止。

1. **予算カテゴリからも、その月に何に使ったかの明細を見たい。**
   いまの予算画面は `budget_allocations` の枠をいじる場所で、`entries` は1件も出していない。
   カテゴリ別の金額は分析画面にあるが、集計値だけで明細は並ばない。
2. **口座の明細が編集できない。** `/accounts` は口座をタップすると直近60件が出るが、
   行は `<div className="tx-row" style={{cursor:'default'}}>` で押せない（`AccountsPage.tsx:434`）。
3. **家の PC から付けた記録の座標が全部おかしい。** リセットしたい。
4. **PC からは位置情報を付けないでほしい。**

### 3・4 の実態

**このアプリは逆ジオコーディングをしていない。** 保存しているのは座標だけで、
住所文字列はどこにも作っていない（Azure Maps の POI・逆ジオは日本で使い物にならず不採用）。
画面の場所名はすべて `COALESCE(merchant, place_name)`＝人が入力した文字列。

したがって「よくわからない住所」の実体は、**PC の Wi-Fi/IP 測位による数km ずれた座標**が
支出マップのピンと📍地図リンクを見知らぬ場所へ飛ばしている状態。

**既存の手段では消せない。**

| 手段 | 実際に何をするか |
|---|---|
| `PUT /api/home`（自宅登録）→ `clearNearby` | **自宅の円内だけ**座標を消す。今回のズレた座標は圏外 |
| `DELETE /api/home` | `households.home_lat/lng` を NULL にするだけ。記録には触れない |
| `PATCH /api/entries/{id}` | UPDATE 文に位置列が無い（`entries.ts:307-327`）。編集画面から消せない |

**精度による足切りはどこにも無い。** `location_accuracy` は保存も表示もしているが
（`QuickAddSheet.tsx:191` ほか）、判定には一切使われていない。
`useGeo` は誤差が何 m でも `state='ready'` にしてそのまま採用する（`lib/geo.ts:56-69`）。

**デバイス判定は JS に1つも無い。** `userAgent` / `matchMedia` / `maxTouchPoints` はゼロ件。
`isGeoEnabled()` は localStorage が `'off'` でなければ true ＝ **既定 ON**（`geo.ts:19-22`）。

### 合意済みの前提（Q&A で確定）

1. リセットは**精度の悪いものだけ**消す。実行前に「何件消えるか」を見せる
2. PC 判定は**デバイス判定＋サーバー側の精度切り捨て**の二重
3. リセットは**自宅ページのボタン**（マイグレーションの手動適用を増やさない）
4. 予算の明細は**カテゴリ行を押すとシート**（口座画面と同じ作り）

## 設計の要点

### 取引の編集シートを共有部品にする

編集の入口がカレンダー・口座・予算の3つになる。複製すると必ず片方だけ直る。
`CalendarPage` が抱えている編集シート（`EntryForm` + PATCH + 削除 + 取り消し + 定期変換）を
`features/entries/EntryEditSheet.tsx` へ切り出し、3画面から使う。

**新規作成は切り出さない。** 現在地・自宅判定・連続入力は記録するときだけの関心で、
口座や予算から新規に作る導線は無い。`CalendarPage` のシートは作成専用として残る。

「この支出を返金」は `onRefund?` の任意コールバックにする。カレンダーだけが渡し、
他は渡さない＝ボタンが出ない。返金は新規作成に落ちる操作なので、作成の導線がある画面だけの機能。

### シートが2枚重なる

口座・予算はどちらも「一覧シートの中の行を押して編集シート」になる。
`.sheet-backdrop` は `z-index:40`、`.sheet` は `50`（`tokens.css:544-559`）なので、
内側の背景が外側のシートの**下**に潜って外側が暗くならない。

`Sheet` に `layer?: 1 | 2` を足し、2 のときだけ `60 / 70` を使う。
外側を閉じずに済むので、**編集を閉じたら元の一覧に戻る**（画面状態を失わせない）。

### 予算の明細は BE 追加なし

`GET /api/entries` は既に `from` / `to` / `categoryId` を受ける（`entries.ts:119-148`）。
`?categoryId=X&from=YYYY-MM-01&to=YYYY-MM-末` で足りる。口座明細が
`?accountId=` を流用したのと同じやり方。

**プール負担の支出は出ない。** `budget_category_id` が NULL のため。
これは正しい（予算カテゴリを消費していない）が、合計が `spent` と一致するので混乱は無い。

### 位置情報のリセットは精度で選ぶ

PC の Wi-Fi/IP 測位は通常 1000m 以上、スマホの GPS は 5〜50m。誤差で分離できる。

`GET /api/locations/summary` が **200m / 500m / 1000m 超の件数**をまとめて返し、
画面はそれを見せてから消させる。**何件消えるか分からないまま押せるボタンにしない**
（月次締めのプレビュー→承認と同じ考え方）。

`POST /api/locations/clear` は `{ minAccuracy }` を受け、`entries` と `entry_stock` の
`lat / lng / location_accuracy` を NULL にする。**`merchant` / `place_name` / 金額は残す**
（`clearNearby` と同じ扱い）。

`location_accuracy` が NULL で座標だけある行は**消さない**が、件数は summary に出す。
判断材料を隠さないため。実際には `useGeo` が必ず accuracy を入れるので 0 件のはず。

### PC で位置を取りに行かない

`isGeoEnabled()` の既定をデバイスで分ける。**明示的に設定した値は常に優先する。**

```
localStorage に 'on' / 'off' があればそれに従う
無ければ  タッチできる端末（any-pointer: coarse）→ ON
          それ以外（マウスだけ＝PC）           → OFF
```

加えて **BE で誤差の大きい座標を捨てる**（`domain/geo.ts` に純粋関数、
`entries.ts` と `stock.ts` の `stripIfAtHome` の直前に置く）。
`normalizeEntry` が種別ごとの項目を落とすのと同じで、**画面の作りには依存させない**。
タッチ対応ノート PC や、屋内で GPS が掴めないスマホもこれで拾える。

**自宅の登録だけは別扱い。** `PUT /api/home` は精度で弾かない（弾くと登録できなくなる）が、
誤差が大きいときは画面で警告する。**PC から自宅を登録すると数km ずれた自宅ができ、
以後の自宅判定が全部おかしくなる**ため、ここは黙って通してはいけない。

## 手順

既存に手を入れる工程を先に単独で終わらせ、確認してから新しい画面を作る。

1. `91_UPDATE/11/` に予定書
2. BE `domain/geo.ts` の純粋関数 → `entries.ts` / `stock.ts` に適用
3. BE `functions/locations.ts` と `index.ts`
4. FE `lib/geo.ts` のデバイス判定、`lib/queries.ts`
5. FE `Sheet` の `layer` と CSS。**この時点で既存のシートが変わっていないことを確認**
6. FE `EntryEditSheet` を切り出し、`CalendarPage` を差し替え。
   **カレンダーの編集・削除・取り消し・返金・定期変換が今までどおり動くことを確認**
7. FE `AccountsPage` の明細を押せるように
8. FE `BudgetPage` のカテゴリ明細シート
9. FE `HomePage` のリセットと警告
10. 型チェック・ビルド・見た目確認
11. ドキュメント更新（`21/` 完了記録、`system_flow.md` の自宅・支出マップの節）

## 検証

```
cd 11_BE_DEPLOYMENT && npm run build
cd 10_SITE_DEPLOYMENT && npm run typecheck && npm run build
```

`domain/geo.ts` は純粋関数なので `dist` に対して直接確かめる（これまでと同じやり方）。

- `dropIfImprecise` が閾値ちょうど（500m）を残し、501m を捨てる
- 座標が無い入力、accuracy が null の入力で落ちない
- 座標を捨てるときは `lat` / `lng` / `locationAccuracy` の3つとも null になる

画面（実 DB が要らない範囲）:
- マウスだけの環境で `isGeoEnabled()` が false、タッチ環境で true。
  localStorage に明示値があればどちらの環境でもそれが優先される
- シートが2枚重なったとき、内側の背景が外側を覆う（外側が暗くなる）
- 予算のカテゴリ行・口座の明細行がキーボードで辿れる（`<button>` になっている）

デプロイ後に実データで確認すること:
1. 自宅ページで「誤差500m超 N件」が出る。**押す前に件数が分かる**
2. リセット後、支出マップから変なピンが消える。**金額・店名・カテゴリは残っている**
3. PC で記録しても位置が付かない。スマホでは今までどおり付く
4. 予算のカテゴリを押すとその月の明細が出て、合計が行の「使った」と一致する
5. 口座・予算のどちらから直しても、カレンダーと残高に反映される
6. PC で自宅を登録しようとすると警告が出る

## 懸念点

1. **`CalendarPage` の編集シートを動かす。** いちばん使う画面なので、
   切り出しは「振る舞いを変えない」を厳守し、その工程だけで一度確認する
2. **閾値 500m は当て推量。** 実データの誤差分布を見ていない。
   summary が 200 / 500 / 1000m の件数を返すので、**それを見てから決められる**ようにしてある。
   BE の切り捨て閾値も同じ値を使うので、ずれていたら定数1つで直る
3. **タッチ対応ノート PC は「スマホ」と判定される。** デバイス判定だけでは漏れるので、
   サーバー側の精度切り捨てを併せて入れている
4. **リセットは元に戻せない。** 座標は復元できない。件数を見せてから実行させる
5. **プール負担の支出は予算の明細に出ない。** 仕様どおりだが、
   「使った額」と明細の合計が一致することは確認しておく
