## 決めたこと

- **束ねる鍵は座標のかたまり。地名は表示のための飾り。**
  町境の近くの店は GPS のばらつきで町名が変わりうるので、「店名＋地名」を鍵にすると割れる
- 同じ店とみなす距離は **200m**（店名候補の約150mより少し広い。大型店は入口と駐車場で離れる）
- **地名は国土地理院から取る。API キーが要らない**ので方針を崩さずに済む
- **地名は定時ジョブ（15分ごと）が埋める。** 記録の保存では外部 API を呼ばない
- **記録に書く店名は利用者の呼び方のまま。** 地名は表示にだけ使う
- 初回の埋め戻しはマイグレーションの中で行う（**外部 API を呼ばない**。地名は後から）

## 注意する点

- **適用の順序: マイグレーション → BE デプロイ。** 逆にすると BE が存在しない列を触って 500 になる
- **座標なしのマスタは新しく作らない。** 座標が無いものを作っても店を区別できず、
  後から現地で記録したときに別のマスタができて店が2つに割れる
- **座標なしマスタは「育てる」。** 一括登録しか無かった店に初めて現地から記録したら、
  新規作成ではなくそのマスタへ座標を書き込む。割らないため
- **座標が無く同名が複数なら紐付けない。** 当てずっぽうに選ぶと金額が別の店に混ざり、
  後から気付けない
- **紐付けに失敗しても記録は巻き戻さない。** 記録は残っているほうが常に良い（定期取引と同じ判断）
- **一括登録は1文でまとめて紐付ける。** 行ごとに引くと 50 行で 50 往復になり、
  この機能が往復を増やさないために払った工夫が無駄になる
- `domain/muni.ts` は国土地理院 `muni.js` からの**生成物**。実行時に取りに行かない
  （合併でしか変わらないので、黙って壊れるより手作業で気付ける形にする）
- DB の計算列 `display_name` と `domain/place.ts` の `displayName()` は**同じ規則にすること**
