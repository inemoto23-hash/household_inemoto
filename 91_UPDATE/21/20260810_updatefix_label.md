# 20260810 不具合修正記録（label のクリック転送で選択がすり替わる）

- **区分**: 軽微修正（計画スキップ）
- **報告**: 「設定/予算の給与、その他収入が、設定したら支出カテゴリに行ってしまった」

## 症状

収入カテゴリを編集して保存すると、種別が支出に変わってしまう。

## 原因

`components/ui.tsx` の `Field` を `<label>` で実装していた。

**`<label>` 内をクリックすると、ブラウザは「最初の操作可能な子要素」へクリックを転送する。**
種別欄には 支出 / 収入 の2つのボタンが入っていたため、

1. 収入 を押す → `kind = 'income'`
2. ブラウザが先頭の 支出 へクリックを転送 → `kind = 'expense'`

という順で必ず上書きされていた。

同じ構造の欄が他にもあり、いずれも壊れていた。

| 欄 | 症状 |
|---|---|
| 口座の種別（5択） | 何を選んでも銀行になる |
| 色（12択） | どれを押しても先頭の色になる |
| アイコン（96択） | 絵文字を押すと直後に「外す」が押され、設定できない |

「設定画面の操作性が悪い」という指摘の実体はこれ。

## 対処

`FieldGroup`（`<div role="group" aria-label>`）を追加し、選択肢が複数並ぶ8箇所を差し替えた。

入力欄がひとつだけの欄は `<label>` のまま残す。ラベルを押すと入力欄へ移る挙動は有用で、
かつ**操作可能な子がひとつなら転送先は自分自身**なので問題が起きない。

`Field` の説明に「操作可能なものを2つ以上入れてはいけない」と明記した。

## データの復旧

`給与` と `その他収入` の `kind` を `income` へ戻した。

今月（2026-08）の `budget_allocations` は確認済みで**破損なし**。
各カテゴリの配分合計は設定した既定額と一致しており、
収入カテゴリは `budgetsGet` の集計で expense のみを合算するため、支出側にも混入していない。

> アイコンと色はこの不具合の間、正しく保存できていなかった可能性がある。設定し直しが必要。
