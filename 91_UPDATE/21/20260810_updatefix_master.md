## 完了内容

### データベース

`006_opening_date.sql` を適用。`vw_account_balances` が `opening_date` より前の取引を
合算しないようにした。振替の相手口座側にも同じ条件をかけている。

> 期首残高は「その日時点の残高」を表す。ビューが全期間を合算していたため、
> 期首日より前の取引があると期首残高と二重に効いてしまう状態だった。

### バックエンド

`src/functions/master.ts` を新設。10 エンドポイント。

| メソッド | ルート |
|---|---|
| POST / PATCH / PUT | `/api/accounts` `/api/accounts/{id}` `/api/accounts/order` |
| POST / PATCH / PUT | `/api/categories` `/api/categories/{id}` `/api/categories/order` |
| GET / POST / PATCH / PUT | `/api/pools` `/api/pools/{id}` `/api/pools/order` |

DB の CHECK 制約と同じ判断をサーバ側でも行う。

- `normalizeCreditFields()` — 種別がクレジット以外なら 締め日・支払日・支払口座を NULL にする
- `normalizeCarryOver()` — 繰越先が `to_pool` 以外なら 集約先プールを NULL にする
- 一意制約違反（2627 / 2601）を 409 `DUPLICATE_NAME` と日本語メッセージへ変換

あわせて `accountsList` の返却に `openingBalance` / `openingDate` / クレジット3項目を追加した。
編集フォームがこれらを必要とするため。

### フロントエンド

#### 管理画面 `/manage`

`features/master/ManagePage.tsx`。口座 / カテゴリ / プール の3タブ。

- 追加・編集はシート。既存の編集体験と揃える
- 並べ替えは上下ボタン。ドラッグはスマホで誤爆しやすいため採らない
- 色は10色のスウォッチから選ぶ。自由入力は画面全体の統一感が崩れる
- クレジットを選んだときだけ 締め日・支払日・引き落とし口座が現れる
- **削除は用意しない。** 保管（アーカイブ）に切り替える
