### 判断したこと

**ブラウザから Azure Maps を直接呼ばない。** 直接呼ぶには次のどちらかが要る。

| 方式 | 問題 |
|---|---|
| FE にサブスクリプションキー | 「接続文字列とAPIキーを持たない」方針に反する |
| FE が Entra トークン + RBAC | メンバーが増えるたびに Azure 側で権限付与が要る |

BE で中継すれば、認証は今までどおりアプリの Bearer トークンだけで済む。
利用者側の Azure 設定は一切不要になる。

**静的地図（画像）を選び、ベクタータイル＋地図ライブラリは採らなかった。**
現行 API の道路地図はベクター形式のみで、ブラウザで描くにはスタイル定義・
グリフ・スプライトもすべて中継が要る。得られるのは拡大縮小と移動だが、
世帯の支出先はせいぜい10件程度で、そのために増える部品が見合わない。

**拡大率はこちらで計算する。** Azure Maps は `bbox` と `width`/`height` を
同時に受け付けない（`400 Bbox may not be used in conjunction with center and/or width and/or height`）。
出力サイズを指定するなら中心と拡大率を渡すしかない。

**静的地図は1タイル512画素。** ここが今回いちばん間違えやすかった点。
256 で計算すると拡大率が1段きつくなり、実際に4地点中3地点が画像からはみ出した。
描かせた画像でピンの位置を実測して 512 と確定した。

**地図が出せなくても分析画面は使える。** 位置つきの記録が無ければ `204`、
取得に失敗したら `502` を返し、場所ごとの一覧はそのまま表示する。

## 4. フロントエンド

`features/analytics/AnalyticsPage.tsx` に `SpendingMap` を追加。

- 画像は `fetchBlob`（アバターで使っているもの）で取得する。
  トークンが要るため `<img src>` では読めない
- 幅は 40px 単位に丸めて頼む。少しの差で問い合わせ直さないため
- 端末の画素密度（最大2倍）を掛けた大きさで取得し、CSS で等倍表示する
- React Query の `staleTime` を1時間、レスポンスにも `Cache-Control: private, max-age=3600`

**一覧の行にピンと同じ番号を出す。** どちらも「位置つきを金額の多い順に上位10件」で
数える。ずれると、どの棒がどのピンか分からなくなる。

## 8. 後片付け

検証のために自分のユーザーアカウントへ一時的に付けた `Azure Maps Data Reader` は削除した。
**利用者本人に Azure のロールを持たせない**という今回の設計をそのまま保つため。
再度画像を直接取得して確かめたくなったら、次の1行で戻せる。

```
az role assignment create --assignee-object-id <自分のobjectId> \
  --assignee-principal-type User --role "Azure Maps Data Reader" \
  --scope /subscriptions/<sub>/resourceGroups/inemoto_KakeiFlow_RG/providers/Microsoft.Maps/accounts/inemoto-KakeiFlow-Maps
```

> Git Bash から az を叩く場合は `MSYS_NO_PATHCONV=1` が要る。
> 付けないと `/subscriptions/...` が Windows のパスへ変換され、
> `MissingSubscription` で失敗する。
