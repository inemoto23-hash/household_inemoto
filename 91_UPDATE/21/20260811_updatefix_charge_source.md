# 20260811 アップデート完了記録（チャージ元の固定）

- **予定書**: `91_UPDATE/11/20260811_update_charge_source.md`
- **ユーザー手動手順**: なし（設定 → 口座 で印を付ける操作は必要）

## やったこと

チャージ元は実際には常に同じ口座なので、記録のたびに選ばせない。
口座に印を付けておき、記録画面では**チャージ先だけを選ぶ**。

## データベース

`20_DATABASE/migrations/015_charge_source.sql`（適用済み）。

```sql
ALTER TABLE dbo.accounts ADD is_charge_source BIT NOT NULL DEFAULT 0;

CREATE UNIQUE INDEX ux_accounts_charge_source
    ON dbo.accounts (household_id)
    WHERE is_charge_source = 1;
```

### 判断したこと

**世帯にひとつという決まりは DB に守らせる。** フィルタ付き一意インデックスを張り、
2つ立つことが構造的に起きないようにした。付け替えは
「先に他を落としてから立てる」をアプリが行うが、**落とし忘れれば索引が必ず弾く**。
画面の作りにも、書き忘れにも依存しない。

**種別は縛らない。** クレジットからも銀行からもチャージするため。

**新しいテーブルは作らない。** 既存の「クレジットの引き落とし口座」
（`accounts.payment_account_id`）と同じ場所に、同じ作法で足した。

## フロントエンド

### 設定 → 口座

編集シートに「この口座をチャージ元にする」を置いた。
すでに別の口座に付いている場合は**その名前を出し、付け替えになることを伝える**。
黙って外れる作りにはしない。

一覧にも「🔌 チャージ元」と出るので、どれに付いているか開かずに分かる。

### 記録画面

チャージのときだけ並びを変えた。

| 以前 | いま |
|---|---|
| どこから → チャージ先 | **チャージ先** → チャージ元（固定表示） |

チャージ元は名前と残高を文字で見せ、右に小さく「変更」。
押すと今までの選択欄が出る。**普段は選ぶ必要がないが、塞がってもいない。**

属性が未設定なら選択欄を出し、「設定の口座でチャージ元を決めると、次から自動で入ります」
と添える。付けていなくても今までどおり記録できる。

**種別の切り替えは効果ではなく操作の中で行う。**
効果にすると、既存のチャージを編集で開いたときにも走り、
記録済みの出どころを属性の口座で上書きしてしまう。
