## 実装方針

**2段構成。Phase A はプロダクションコード無変更、Phase B は挙動不変の抽出リファクタのみ。**

### Phase A: Vitest 導入＋既存純粋関数のテスト

- devDependencies に `vitest` を追加（本計画唯一の新規依存）
- `vitest.config.ts`（`test/**/*.test.ts`、environment node）、scripts に `test` / `test:watch`
- テストは `test/` 直下（`src/` 配下だと `tsc` の `dist/` 出力へ混入。`.funcignore` は `test` 除外済み）
- 対象と必須ケース:
  - `test/entry.test.ts` — `normalizeEntry`（transfer 両口座必須・同一口座禁止・カテゴリ/プール強制null、
    income カテゴリ必須、expense/refund の**カテゴリ⊕プール排他** = `ck_entries_shape` のアプリ側鏡像）、`monthRange`
  - `test/geo.test.ts` — `distanceMeters` / `isAtHome`（半径境界）/ `dropIfImprecise`（accuracy 500/501/null）/ `boundingBox`
  - `test/place.test.ts` — `matchPlace` **7分岐全網羅**、`normalizePlaceName`、`displayName`
  - `test/recurrence.test.ts` — 月末丸め（31日→2月28/29日→31日へ復帰）、隔週、endDate、
    `occurrencesUpTo`（limit 12・skipBefore 62日の冪等性）、`todayJst` への Date 注入
  - `test/schedule.test.ts` — 終日9:00基準・JST→UTC・オフセット表記
  - `test/convert.test.ts` — `num`/`numOrNull` の throw 分岐
  - `test/maps.test.ts` — `fitView` の縮退・クランプ
  - `domain/muni.ts` は定数テーブルのみでテスト価値が低く対象外

### Phase B: 宣言済み優先項目のための最小抽出（挙動不変）

- **B-1 繰越計算**: `functions/periods.ts:89-125` の行マッピングを純粋関数
  `computeCloseLines(rows)` として新規 `src/domain/period.ts` へ抽出。`nextMonth`/`prevMonth`/`lastDay` も移動。
  `computeLines` は「SQL → `computeCloseLines`」の合成へ（プレビューと実行の共有構造は不変）。
  `test/period.test.ts` で policy 4種（none/surplus/full/to_pool）・年跨ぎ・閏年を固定
- **B-2 ゼロサム**: 3箇所に散在する符号付きペア生成（`budgets.ts:507-510`・`budgets.ts:574-581`・
  `periods.ts:261,277`）から `buildTransferPair()` を切り出して一本化。
  `test/allocation.test.ts` で「対の合計が常に0・同一 groupId・方向別の符号」を固定
