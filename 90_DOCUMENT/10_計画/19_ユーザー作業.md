## 1. Google フェデレーション設定（Gmail でサインインできるようにする）

現在、Entra テナントには `inemoto23@gmail.com` が **ゲストユーザー**として登録済み（`inemoto23_gmail.com#EXT#@inemoto23gmail.onmicrosoft.com`）。
このままだと **Microsoft アカウント**としての認証になる。**Google のパスワードでサインイン**したい場合に本設定が必要。

> 未設定でもサインイン自体は可能（Microsoft アカウント経由）。急がなくてよい。

### 1-1. Google Cloud Console 側

1. https://console.cloud.google.com/ を開く
2. プロジェクトを新規作成（例: `KakeiFlow-Auth`）
3. **API とサービス → OAuth 同意画面**
   - User Type: **外部**
   - アプリ名: `KakeiFlow`
   - サポートメール / 開発者連絡先: 自分の Gmail
   - スコープ追加は不要（既定の email / profile / openid のみ）
   - テストユーザーに **自分と配偶者の Gmail アドレスを追加**
     （公開申請しなくてもテストユーザーなら使える）
4. **API とサービス → 認証情報 → 認証情報を作成 → OAuth クライアント ID**
   - アプリケーションの種類: **ウェブ アプリケーション**
   - 名前: `KakeiFlow-Entra`
   - **承認済みのリダイレクト URI** に以下**3つ**を登録（1つでも欠けると失敗する）

     ```
     https://login.microsoftonline.com
     https://login.microsoftonline.com/te/1e2f5217-4ca1-4762-a0b6-a9f16f29d4c6/oauth2/authresp
     https://login.microsoftonline.com/te/inemoto23gmail.onmicrosoft.com/oauth2/authresp
     ```

   - **承認済みドメイン**に `microsoftonline.com` を追加する

5. 発行された **クライアント ID** と **クライアント シークレット** を控える

### 1-2. Microsoft Entra 側

**方法A: 管理センターの画面から**

1. https://entra.microsoft.com/ を開く（`inemoto23@gmail.com` でサインイン）
2. **Entra ID → 外部 ID → すべての ID プロバイダー**
3. **Google** の行で「構成」を選択
4. 1-1 で控えた **クライアント ID / クライアント シークレット**を貼り付けて保存

**方法B: PowerShell から（画面が開かない場合はこちら）**

管理センターの「すべての ID プロバイダー」が表示されない場合、以下で同じ設定ができる。

```powershell
Install-Module Microsoft.Graph -Scope CurrentUser
Connect-MgGraph -Scopes "IdentityProvider.ReadWrite.All"

$params = @{
   "@odata.type"        = "microsoft.graph.socialIdentityProvider"
   displayName          = "Login with Google"
   identityProviderType = "Google"
   clientId             = "<Google のクライアントID>"
   clientSecret         = "<Google のクライアントシークレット>"
}
New-MgIdentityProvider -BodyParameter $params

# 確認
Get-MgIdentityProvider
```

> `Connect-MgGraph` 実行時にブラウザで同意画面が出る。`inemoto23@gmail.com` で承認すること。

### 1-2-a. 画面が開かないときの確認事項

- `Microsoft.AzureActiveDirectory` リソースプロバイダーの登録 → **2026-08-10 に登録済み**
- 必要なロール: **External Identity Provider Administrator** 以上 → **Global Administrator を保有済み**
- それでも表示されない場合は、ブラウザのキャッシュ削除またはシークレットウィンドウで再試行する
- 上記でも解決しない場合は **方法B（PowerShell）**を使う。機能的には同一

### 1-3. 動作確認

1. ブラウザのシークレットウィンドウで https://black-sea-0e3c5e400.7.azurestaticapps.net/ を開く
2. 「サインイン」→ Gmail アドレスを入力
3. **Google のログイン画面にリダイレクトされれば成功**

### 注意点

- **`@gmail.com` のみ対応。** Google Workspace の独自ドメインは別設定（SAML/WS-Fed）が必要
- **Google は埋め込み WebView でのサインインをブロックしている。** iOS のホーム画面 PWA から初回サインインが弾かれる可能性があるため、必ず実機で確認すること。弾かれる場合はサインインのみ外部ブラウザで開く導線に切り替える（実装で対応可能）
- Google のクライアントシークレットは **Entra が保持**する。こちらでファイルに保存する必要はない

## 3. ストレージアカウントキー → 対応済み（作業不要）

当初 Function App の `AzureWebJobsStorage` にストレージアカウントキーが平文で設定されていたが、
**マネージドID方式へ切り替え済み**のため対応不要になった。

実施内容:
- MI に `Storage Blob Data Owner` / `Storage Queue Data Contributor` / `Storage Table Data Contributor` を付与
- `AzureWebJobsStorage` を `AzureWebJobsStorage__blobServiceUri` などの ID ベース設定へ置換
- Flex Consumption のデプロイ用ストレージ認証を `SystemAssignedIdentity` へ変更
- ストレージアカウントの **`allowSharedKeyAccess = false`**（共有キーによるアクセスを禁止）

**これにより作業ログへ出力された旧キーは無効化されたため、ローテーションも不要。**
キーを使う経路自体がストレージ側で塞がれている。
