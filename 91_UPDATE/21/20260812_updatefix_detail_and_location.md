## 分かったこと（調査の結果）

**このアプリは逆ジオコーディングをしていない。** 保存しているのは座標だけで、
住所文字列はどこにも作っていない（Azure Maps の POI・逆ジオは日本で使い物にならず不採用）。
画面の場所名はすべて `COALESCE(merchant, place_name)`＝人が入力した文字列。

「よくわからない住所」の実体は、**PC の Wi-Fi/IP 測位による数km ずれた座標**が
支出マップのピンと📍地図リンクを見知らぬ場所へ飛ばしていた状態だった。

**既存の手段では消せなかった。**

| 手段 | 実際に何をするか |
|---|---|
| `PUT /api/home` → `clearNearby` | **自宅の円内だけ**。ズレた座標は圏外 |
| `DELETE /api/home` | `households.home_lat/lng` を NULL にするだけ。記録には触れない |
| `PATCH /api/entries/{id}` | UPDATE 文に位置列が無い。編集画面から消せない |

**精度による足切りはどこにも無かった。** `location_accuracy` は保存も表示もしていたが、
判定には一切使われていなかった。**デバイス判定も JS に1つも無かった。**

### 判断したこと

**入口の2段構えにした。** 画面側は「マウスしか無い端末では位置を取りに行かない」、
サーバー側は「誤差 500m 超を捨てる」。
**画面側だけでは足りない** — タッチできるノートPC や、屋内で GPS を掴めないスマホが
すり抜ける。`normalizeEntry` が種別ごとの項目を落とすのと同じで、
**画面の作りには依存させない**。

**捨てる順番は「精度 → 自宅」。** 精度で落ちた座標は自宅判定にかける意味がないうえ、
`stripIfAtHome` は自宅が未登録なら素通しするので、先に精度で削らないと残ってしまう。

**誤差が分からない（NULL）ものは通すし、消さない。**
値が無いことは「悪い」ことの証拠にならない。件数は summary に出して判断材料は隠さない。

**消す前に件数を見せる。** 座標は元に戻せない。段階（200/500/1000m）ごとの件数を返し、
選んでから押させる。**何件消えるか分からないまま押せるボタンにしない**
（月次締めのプレビュー→承認と同じ考え方）。

**消すのは座標の3列だけ。** `merchant` / `place_name` / 金額は残す。
自宅登録時の `clearNearby` と同じ扱いに揃えた。あちらが「自宅の円内」で選ぶのに対し、
こちらは「誤差の大きさ」で選ぶ。

**`recurringSweep` のような追いつき処理とは別物。** 入口で止めるのが正しい。

### 判断したこと

**編集シートを1つの実装にした。** 入口がカレンダー・口座・予算の3つになる。
複製すると必ず片方だけ直る。`EntryEditSheet` が PATCH・削除・取り消し・定期変換を持つ。

**新規作成は切り出さなかった。** 現在地・自宅判定・連続入力は「記録するとき」だけの関心で、
口座や予算から新しく作る導線は無い。`CalendarPage` のシートは**作成専用**になった。
「この支出を返金」は新しい記録を作る操作なので `onRefund` の任意コールバックにし、
作成の導線があるカレンダーだけが渡す＝他ではボタンが出ない。

**シートの重なりを直した。** `.sheet-backdrop`(40) が `.sheet`(50) より下にあるため、
2枚重ねると**内側の背景が外側のシートの下に潜り、外側が暗くならない**。
`layer={2}` で 60/70 を使う。外側を閉じずに済むので、**編集を閉じれば元の一覧に戻る**。

**予算の明細は BE 追加なし。** `GET /api/entries` が既に `from`/`to`/`categoryId` を
受けるので `?categoryId=X&from=YYYY-MM-01&to=YYYY-MM-末`。
口座明細が `?accountId=` を流用したのと同じやり方。

**プールから出した支出は予算の明細に出ない。** `budget_category_id` が NULL のため。
予算カテゴリを消費していないので正しいが、気付けるようシートに一文を出した。

**配分を直しているあいだはカテゴリ行を押せない。** 入力欄と明細を開く操作が
同じ場所にあると押し間違える。`editingInitial` のときは元の `<span>` に戻す。

**`refreshLedger` を切り出した。** 前回 `20260812_updatefix_bulk.md` の残課題。
呼ぶ場所が3つ増えたのでここで片付けた。
**口座画面の残高は `['manage', 'accounts']` で引いている**ため、キーの並びに
`['manage']` を入れないと残高だけ古いまま残る。

**PC からの自宅登録は止めないが警告する。** 弾くと登録そのものができなくなる。
**ずれた自宅を登録すると以後の自宅判定がすべて狂う**ので、黙って通してはいけない。
誤差が切り捨て境目を超えているときも、取得後に赤字で出す。

**「位置情報を使う」と自分で決めた設定は常に優先される。** 端末で決めるのは既定値だけ。
案内の文言も「切られています」と「既定で使いません」で分けた（`isGeoChosen`）。
