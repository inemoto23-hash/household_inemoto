実装工程に入った場合、下記を遵守して作業を行うこと。

## 成果物の配置
- ソースコード本体は `80_bin/{システム}/{機能}/` に配置する（システム = common / db / poller / builder / features / train / raceday / publish）
- 起動スクリプト（bat / ps1）は `01_TOOL/` に配置する。実装本体は置かず、80_bin のコードを呼び出すだけにする
- DDL・DB ドキュメントは `90_DOCUMENT/02_DB情報/` に配置する（DDL 本体は `DDL/`、解説は `DDL解説/`、設計は `schema_design.md`）
- サイト FE は `10_SITE_DEPLOYMENT/`、サイト BE（Azure Functions）は `11_SITE_FUNCTION_LB/` に配置する
- 中間生成物は `04_TMP1/`、実験・一時作業は `05_TMP2/`、出力（モデル成果物含む）は `03_OUTPUT/` に配置する
- プロジェクトルートの `.env` は AI による読取禁止。ツールは python-dotenv 経由で読む（キー名の記載は可、値は不可）

## ファイル分割方針
- 実装は**機能ブロックごとに 1 ソースファイル**を持つようにする
- 1 ファイルが肥大化しないこと
- 既存ファイルへの追加実装を決定した場合も、肥大しそうであれば分割を検討すること
- 分割の目安: 300 行を超える、または複数の責務が混在している場合

## ドキュメント更新（実装完了後に必須）
実装完了後、以下を**必ず**更新すること：

### 毎回更新
- `90_DOCUMENT/system_architecture.md` — 構成変更を反映
- `90_DOCUMENT/system_flow.md` — フロー変更があれば更新
- `90_DOCUMENT/file_map.md` — 新規・変更ファイルを反映（下記参照）

### ソースファイル単位で更新
- `90_DOCUMENT/01_開発ドキュメント/<ファイル名>.md` — 対象ソースコードの要約・注意点を記載・更新する
- DDL（.sql）の解説は `90_DOCUMENT/02_DB情報/DDL解説/<ファイル名>.md` に置く

## file_map.md の更新ルール
- **新規ファイルを作成した場合**: `file_map.md` へ 1 行コメントと依存関係を追記する
- **ファイルを削除・移動した場合**: `file_map.md` から該当エントリを削除・修正する
- **ファイル間の新たな依存関係が生まれた場合**: 繋がりセクションを必ず更新する
- `file_map.md` の更新を忘れた場合、その実装は**未完了**とみなす
