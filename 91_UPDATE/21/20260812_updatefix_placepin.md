## 3. 代表座標を `AVG` から変えた

平均は外れ値1件で引きずられ、**同名の別店舗は中間（どちらでもない場所）**に立つ。

T-SQL は `GROUP BY` の中で「特定の行の値」を直接取れないため、窓関数で順位を振ってから拾う。

```sql
ROW_NUMBER() OVER (
  PARTITION BY COALESCE(e.merchant, e.place_name)
  ORDER BY CASE WHEN e.lat IS NULL THEN 1 ELSE 0 END,  -- 座標つきを先に
           e.entry_date DESC, e.id DESC                 -- その中で新しいもの
) AS rn
...
MAX(CASE WHEN rn = 1 THEN lat END) AS lat
```

`rn = 1` は「座標つきのうちいちばん新しい行」。その店に座標つきが1件も無ければ
座標なしの行になり、`lat` は NULL のまま＝地図に出ない。**望む挙動そのまま。**

**`OUTER APPLY` で店ごとに引き直す書き方は採らなかった。** Basic 5DTU では索引探索が
30回積む。窓関数なら月内の行を1回なめるだけで済む。

代表座標は**同じ月の中から**選ぶ。全期間に広げると「その月は座標なしで記録した店」にも
ピンが立ち、位置つきが1件も無い月は地図を出さないという約束が変わる。

## 4. 精度不明の座標を消せるようにした

`locationsClear` は `location_accuracy > 閾値` の行しか消さず、**誤差が分からない行には
逃げ道が無かった**。`includeUnknown` を追加した。

既定は今までどおり消さない（値が無いことは「悪い」ことの証拠にならない）。
画面では**区切り線の下の別ボタン**にして、誤差の大きいものと**まとめて押せない**ようにした。
件数は `summary` の `unknownAccuracy` で押す前に分かる。

消去後は `analytics` / `map` のキャッシュも破棄する。しないと消したのに古い地図が残る。
