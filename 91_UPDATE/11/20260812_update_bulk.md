## やること

記帳の導線が「日付を選ぶ → 1件入力 → 保存」しかないため、レシートの束やカード明細を
まとめて打つときに同じ日付・同じ口座を何度も選び直すことになる。
行を積み上げて一度に登録する画面 `/bulk` を追加する。

1行の項目は **種別（既定=支出）/ 金額 / 日付 / カテゴリ / 口座 / 店先・支払名**。

| 対象 | 内容 |

## 決めたこと

- 種別は **支出・収入・返金のみ**。振替は移動元・移動先で列の意味が変わるので対象外
- カテゴリ欄は**予算カテゴリとプールを2グループに分けた1つの選択欄**
- **部分失敗は認めない。** 1行でも不備があれば何も登録せず、何行目の何が問題かを返す
- **位置情報は受け取らない。** まとめ打ちは店にいないため、付けると支出マップと店名候補を汚す
- `source` は `'manual'` のまま。一括も人が手で打ったもので由来は同じ
- 上限は **50行**

## 注意する点

- **「全か無か」は検証を書き込みの前に終わらせることで作る。**
  zod → `normalizeEntry` → 参照ID の世帯チェックを全行分やり切ってから `begin()` する。
  通常の不備では1行も INSERT されない。DB 制約が発火しても1トランザクションで全部戻る
- **参照ID の検証を行ごとに回さない。** 既存 `assertReferencesInHousehold` は1件で最大3往復。
  50行で150往復になり Basic 5DTU では持たない。ID 集合を作って SELECT を3本並べ、往復1回にする
- **INSERT も1文にまとめる。** 多値 VALUES。パラメータは 11×50=550 で mssql の上限2100に余裕
- **冪等性はバッチ全体に UUID を1つ。** `ux_entries_client_id` が部分ユニーク索引なので、
  全行に同じ値を入れると2行目で違反する。**先頭行にだけ**刻む（＝バッチの受付番号）
- **`PickField` に手を入れる。** 既存6画面が使う部品なので、リスト部分を `PickList` として
  切り出すだけに留め、DOM も見た目も変えない。切り出した直後に既存画面を確認する
- **`accountGroups` / `categoryItem` を `pickOptions.ts` へ移設する。**
  口座の並べ方とクレジットの見せ方が2箇所に分かれると、いずれ片方だけ直る
