# 20260810 アップデート予定（口座・カテゴリ管理 ＋ 外観刷新）

- **区分**: Phase 1（新規画面 + 画面全体の外観刷新）
- **前提**: [91_UPDATE/21/20260810_updatefix_phase1.md](../21/20260810_updatefix_phase1.md) 完了時点

## 背景

口座の**期首残高が全て 0** のままで、財布残高が実態と合わない。
また口座・カテゴリ・プールの追加も改名も並べ替えもできず、実運用に入れない。

あわせて、画面上部のブランド表記と各ブロックの質感が素っ気ないため、外観を整える。

## 1. データベース

### `006_opening_date.sql`

`vw_account_balances` が `opening_date` を無視して**全期間の取引**を合算していた。
期首残高を設定できるようにすると、期首日より前の取引が二重に効いてしまう。

ビューを `entry_date >= opening_date` で絞るよう変更する。振替の相手口座側も同様に絞る。

> 現時点で取引データが無いため、この変更による既存残高への影響は無い。

## 2. バックエンド

`src/functions/master.ts` を新設する。参照系は既存（`accounts.ts` / `bootstrap.ts`）に残し、
このファイルは**マスタの登録・編集・並べ替え・アーカイブ**のみを担当する。

| メソッド | ルート | 内容 |
|---|---|---|
| POST | `/api/accounts` | 口座の追加 |
| PATCH | `/api/accounts/{id}` | 口座の編集・アーカイブ復帰 |
| PUT | `/api/accounts/order` | 並べ替え |
| POST | `/api/categories` | カテゴリの追加 |
| PATCH | `/api/categories/{id}` | カテゴリの編集 |
| PUT | `/api/categories/order` | 並べ替え |
| GET | `/api/pools` | プール一覧（アーカイブ含む取得可） |
| POST | `/api/pools` | プールの追加 |
| PATCH | `/api/pools/{id}` | プールの編集 |
| PUT | `/api/pools/order` | 並べ替え |

**削除は行わずアーカイブする。** 取引が参照しているため物理削除できない。

### 制約に対する防御

DB の CHECK 制約と同じ判断をサーバ側でも行い、**入力を正規化してから**保存する。
（`normalizeEntry` と同じ考え方。画面の作りに依存しない防御を DB とアプリの両方に置く）

| 制約 | サーバ側の正規化 |
|---|---|
| `ck_accounts_credit_fields` | 種別がクレジット以外なら 締め日・支払日・支払口座を NULL にする |
| `ck_bcat_pool_required` | 繰越先が `to_pool` 以外なら 集約先プールを NULL にする |
| `uq_*_name` | 一意制約違反（2627 / 2601）を 409 と日本語メッセージへ変換する |

権限は**世帯メンバー全員**に開放する。メンバー管理（権限に関わる操作）はオーナー限定のままとする。

## 3. フロントエンド

### 新規画面 `/manage`

`features/master/ManagePage.tsx`。口座 / カテゴリ / プール の3タブ。

- 一覧はカード、右端に残高。ドラッグではなく**上下ボタンで並べ替える**（モバイルで確実に操作できる）
- 追加・編集はシート（既存の編集体験と揃える）
- 口座の種別は 銀行 / 現金 / 電子マネー / 投資 / クレジット
- クレジットを選んだときだけ 締め日・支払日・支払口座の欄が現れる
- アーカイブ済みは既定で隠し、切り替えで表示する

### 外観刷新

| 対象 | 変更 |
|---|---|
| ブランド表記 | ロゴマーク（角丸タイル + 流れのグリフ）＋ 字間を詰めたワードマーク。下に世帯名 |
| 上部ナビ | **カレンダー / 予算 / 口座** を1行のセグメント型に。ヘッダーは追従 + 背景ぼかし |
| 下部 | **プロフィール / メンバー / 状態** とサインアウトをフッターへ移動 |
| ブロック | 角丸を大きく、上辺のハイライトと2層の影を追加。`.panel` として共通化 |

トークンを追加し、**3状態（明示light / 明示dark / OS追従）すべてで色を定義する**。
