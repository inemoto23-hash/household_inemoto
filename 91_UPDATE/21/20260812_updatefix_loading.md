## 1. 診断

「サイトを開いてから表示まで時間がかかり、その間 0円 が見えてバグに見える」

**遅さと ¥0 は別の問題だった。**

| 症状 | 原因 |
|---|---|
| 開いてから数秒白い | JS バンドル 180 kB(gzip) の取得・評価と MSAL 初期化を待って初めて描画する |
| その間 ¥0 が出る | `data` 未取得を `?? 0` で 0 に落としてから描いていた |
| 読み込み中に「財布がありません」 | `wallets.length === 0` だけで空を判定していた |

`?? 0` / `?? []` は FE 全体で 40 箇所あるが、**¥0 として実際に画面に出るのは3画面**
（カレンダー・口座・予算）。分析画面は `{data ? … : null}` で元から守られていた。

出る条件は `data === undefined` なので、①初回 ②**別の月へ移動** ③エラー後 の3つ。
タブ移動は同一 queryKey のキャッシュを共有するため、2回目以降は ¥0 にならない。

## 2. スプラッシュ（初回のみ）

**`index.html` に素で置いた。** React コンポーネントにするとバンドルの評価が終わるまで
出ず、いちばん白い時間に間に合わない。FE 側（`components/BootSplash.tsx`）は消す係だけを持つ。

絵は既存 `BrandMark` の波を流す。1周期ぶんを2つ繋げた形を `translateX(-50%)` で送ると
継ぎ目が出ない。上の波 2.4s / 下の波 3.6s と**速度をずらす**（同じだと2本が固まって見える）。
「起動しています」は 1.2 秒過ぎてから薄く出す。速いときは何も語らない。

### 閉じ込めない

| 消す道 | いつ |
|---|---|
| サインイン画面 | 描画時に即 |
| アプリ本体 | `['bootstrap']` の**解決または失敗**時 |
| `main.tsx` | **8秒の安全弁**。上のどちらも来なくても消える |

ロゴが永久に回り続ける画面は真っ白より悪い。原因が一切読めなくなる。
`main.tsx` の「初期化に失敗しても必ず描画する」と同じ判断。

`['bootstrap']` はアプリシェルに張ったが、各画面と同じ queryKey なので**リクエストは増えない**。

最低表示 450ms（速いときのちらつき防止）、フェードアウト 220ms。
経過は `performance.now()`（ページ遷移からの ms）で測る。モジュール側で開始時刻を持つと、
スプラッシュが出たずっと後に評価されるため必ず短く見積もることになる。

## 3. スケルトン

`components/Skeleton.tsx` に `Skeleton` / `MoneySkeleton` / `RowSkeleton`。
`.skel` は `--surface-2` の面を `--surface-hi` の光が 1.4s で横切る。

### 外側は値のときと同じ要素・同じクラスにする

最初は独自の行箱（`display:block; line-height:1.25`）で包んだが、**実測で 3.09px ずれた**。
行の高さは文字ではなく「その要素の行箱」で決まるため、別の入れ物では合わない。

`MoneySkeleton` に `className` と `block` を持たせ、`Money`（インライン `.stat-value`）と
カレンダーの `.money`（ブロック div）を作り分けたところ、**両方とも差 0.00px** になった。

文字幅は実測して `0.47em/文字` に決めた（`.stat-value` は `letter-spacing: -0.03em`、
円記号は 0.6em なので 0.44〜0.50em に収まる）。

### 適用先

| 画面 | 箇所 |
|---|---|
| 口座 | 財布の合計 / 支払予定 / 差し引き、口座一覧 |
| カレンダー | 支出・収入・収支。グリッドは薄くする（日付は出したまま） |
| 予算 | 残り / 消化バー / 消化・予算・調整、カテゴリ一覧 |
| 分析 | 「集計中…」を置き換え（¥0 は元から出ない。見え方を揃えるためだけ） |

カレンダーのグリッドは**日付が並んでいるのに金額が無い**状態になるため、
`opacity: 0.5` + `aria-busy` で「まだ確定していない」と分かる形にした。
金額が無いのを「全部消えた」と読ませない。

## 4. ついでに直した不具合
