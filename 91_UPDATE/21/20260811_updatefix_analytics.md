## バックエンド

`src/functions/analytics.ts` — `GET /api/analytics/{ym}`。

**画面1枚分を1往復で返す。** Basic 5DTU では同時に走らせられる問い合わせが限られるため、
6つの集計を1回の呼び出しにまとめている。

| # | 内容 |
|---|---|
| 1 | 12ヶ月の推移（支出・収入） |
| 2 | カテゴリ別。**今月と前月を同じ行に並べる**ので、増減が1回の集計で出る |
| 3 | 支払い方法別 |
| 4 | 記録した人ごと |
| 5 | 曜日別 |
| 6 | 場所別（上位30件、代表座標つき） |

### 判断したこと

**返金は支出から差し引く。** 収入には混ぜない。カレンダーや予算画面と揃えた。

**曜日は `DATEDIFF(day, '19000107', entry_date) % 7` で数える。**
`DATEPART(weekday)` は `SET DATEFIRST` に左右され、接続の設定次第で結果が変わる。
1900-01-07 は日曜日なので、この式なら常に 0=日曜になる。

**記録の無い月も推移に並べる。** 歯抜けだと折れ線として読めない。

## フロントエンド

`features/analytics/AnalyticsPage.tsx`。上部ナビに「分析」を追加（5項目）。

| 区画 | 見せ方 |
|---|---|
| 収支 | 使った額を主役に、前月比を添える |
| 12ヶ月の推移 | **柱が支出、横線が収入。** 両方を柱にするとどちらを見ているか分からなくなる |
| 何に使ったか | カテゴリ別の横棒 + 前月比 |
| どこで使ったか | 場所別の横棒。座標があれば地図アプリへのリンク |
| どの財布から | 口座別の横棒 |
| 誰が使ったか | メンバー別。アバターつき |
| 曜日ごと | 日曜は赤、土曜は青 |

数字を並べるだけでは「で、どうなの」が分からないため、**前月と比べた増減**を各所に添えている。

### 支出マップについて

地図タイルは敷いていない。場所ごとの合計を棒で並べ、地図で見たい行だけ外部の地図アプリへ飛ばす。

タイル地図の上にヒートマップを描く案は保留とした。理由：

- Azure Maps のリソースを作り直すことになる（POI 品質の問題で削除したばかり）
- ブラウザから地図を出すには、**利用者本人にも Maps の RBAC 付与**が要る
- 家計簿の用途では「地理的な位置」より「何の店か」のほうが重要で、
  店名の一覧のほうが実用的だと判断した
