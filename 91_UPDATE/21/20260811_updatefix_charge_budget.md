## 0. 先に直した不具合：自宅の地図が青一色になる

**原因は `Number(null) === 0`。**

`functions/home.ts` で座標の指定有無を `Number(req.query.get('lat'))` の結果だけで
判定していた。指定が無いと `get()` は `null` を返し、`Number(null)` は `NaN` ではなく **0**。
`Number.isFinite(0)` は真なので、**0, 0（大西洋の真ん中）** の地図を描いていた。

登録中は座標を渡すので正常に見え、**登録後だけ**青くなる、という症状になっていた。

有無の判定を `get()` の戻り値が `null` かどうかで行うよう直した。

### あわせて直した：ピンの文字が `%E5%AE%B6` と描かれる

Azure Maps は非 ASCII のピンラベルを解釈できず、「家」がパーセント符号化された
まま描画される。自宅は1地点なのでラベル自体を外した。
`shared/maps.ts` の `pinsParam` で `label` が空ならラベル無しのピンにする。
ラベルは ASCII（番号）だけにすることを関数のコメントに明記した。

## 1. チャージ

**DB は変えていない。** `kind = 'transfer'` のまま保存する。

### 入力

振替の種類を3つにした。

| 種類 | 元 | 先 |
|---|---|---|
| 口座移動 | すべて | 選んだ元以外 |
| カード引落 | 財布 | クレジット |
| **チャージ** | クレジット + 財布 | **電子マネーのみ** |

行き先を絞ると選び間違いが起きにくい。クレジットから出せば支払予定が積み上がり、
財布から出せば残高が減る。どちらも `transfer` の性質そのままで、特別扱いは要らない。

### 表示は導出する

`lib/format.ts` の `transferLabel(counterAccountId, accounts)` が、
**行き先の口座種別から呼び名を決める。**

- クレジットへ → カード引落
- 電子マネーへ → チャージ
- それ以外 → 口座移動

**保存時の選択を持たせない。** 口座の性質から必ず導けるうえ、
この作りなら**過去の記録も正しい呼び名で読める**。
編集で開いたときの `transferMode` も同じ判定で復元する。

> 種別に `charge` を足す案は採らなかった。残高ビュー・`ck_entries_shape`・
> カレンダー・分析・予算のすべてに手が要り、得られるのは呼び名の違いだけになる。

## 2. 予算タブは「残り」を直す場所にした

### 直したかったこと

予算ページはその月の残高をいじる場所なのに、「配分を設定」が母数まで書き換えていた。

> 食費予算 20000　残高 15000　修正後 10000 にした場合、
> **予算は 20000 のまま、残高は 10000 とする**

### やったこと

同じ台帳を2つの目で読む。`20_DATABASE/migrations/013_alloc_default.sql` で
`ck_alloc_reason` に `default` を追加した。

| 呼び名 | `reason` | 性質 |
|---|---|---|
| **予算（基準額・母数）** | `initial` / `carry_over` / `default` | 残りを直しても動かない |
| 調整 | `adjust` / `transfer` / `to_pool` / `from_pool` | 月内の増減 |

`残り = 基準額 + 調整 − 消化`

新しい `PUT /api/budgets/{ym}/remaining` は
`delta = (消化 + 指定した残り) − 現在の配分合計` を `adjust` で1行追記する。
基準額は `adjust` を含まないので動かない。

画面は「配分を設定」→ **「残りを設定」**。入力欄の初期値も配分額ではなく残り。
行の表示は `使った / 予算` に、調整があれば `調整 −5,000` を添える。

`budgetsSetInitial` は残した。未確定の月を手で埋める用途で要る。

## 3. 翌月は月を締めて初めて決まる

- `budgets.ts` の `ensurePeriod` は `budget_periods` の行を作るだけにした。
  **配分は入れない**
- `periods.ts` の `periodClose` が、繰越を書くのと同じ処理の中で
  既定額を `reason = 'default'` で翌月へ入れる。
  すでに `default` があれば入れないので、締め直しても増えない
- `periodReopen` は翌月の `carry_over` に加えて `default` も消す。
  **手で入れた `initial` / `adjust` は消さない**

画面は、配分が1行も無い月に案内を出す。
先月が未締めなら「先月を締めると決まります」、締め済みなら「残りを設定から入れてください」。

### 既存データの後始末

`20_DATABASE/migrations/014_clear_preseeded_future.sql`。

**9月に既定額が12行・848,944円ぶん入っていた。** 旧来の `ensurePeriod` が、
9月の予算ページを開いた時点で自動投入したもの。放置すると

- 締める前なのに9月が確定して見える
- 8月を締めたときに `default` が重なり、**9月の予算が二重になる**

消したのは機械が入れた行だけ。次の3つをすべて満たすものに絞った。

1. `reason = 'initial'` かつ `note = N'既定の予算から'`（自動投入の印）
2. 今月より後の月
3. その月に取引が1件も無く、締められていない

消す前の内容は `budget_2026-09_allocations` の控えとして取得済み。
削除は12行、8月分（19行・848,944円 + 組み換え4行）は無傷であることを確認した。
