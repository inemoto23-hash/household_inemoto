## 狙い

レジの前でカテゴリと財布まで決めさせない。**金額だけ受け取って即座に保存し、分類は後からまとめて決める。**

確定するまで `entries` に入らないため、**残高にも予算にも影響しない**。
「とりあえず記録した額」が集計を汚さないことが、この機能が成立する前提になる。

## バックエンド

`src/functions/stock.ts` を新設。テーブルは `001_init` の `entry_stock` をそのまま使う（マイグレーション不要）。

| メソッド | ルート | 内容 |
|---|---|---|
| GET | `/api/stock` | 未確定の一覧 |
| POST | `/api/stock` | クイック登録 |
| PATCH | `/api/stock/{id}` | 下書きの編集 |
| POST | `/api/stock/{id}/commit` | 確定して `entries` へ移す |
| DELETE | `/api/stock/{id}` | 破棄（`status = discarded`） |

### 場所からの推測

位置が取れていれば、**同じ場所での過去の記録**からカテゴリ・財布・店名を推測して初期値に入れる。

```
緯度経度が ±0.0015度（日本付近で概ね 140〜170m）の範囲にある
過去の支出を集計し、回数の多い組み合わせを採る。同数なら直近。
```

推測の根拠は `suggestion_reason`（例：「この場所で過去に3件（○○スーパー）」）として保存し、
確定画面に表示する。**なぜその初期値なのかが分からないまま埋まっている状態を作らない。**

学習の材料は確定時に `entries` へ書き戻す位置情報そのもの。専用の学習テーブルは作っていない。

### 確定

`normalizeEntry()` と `assertReferencesInHousehold()` を通常の登録と共有する。
種別ごとの項目整合と世帯チェックが、確定経路でも同じ強さで効く。

`entries` への挿入と `entry_stock` の状態更新は1トランザクション。
`source = 'stock'` を立てるので、どの経路で入った記録か後から分かる。

### 二重登録の防止

`client_id`（UUID）を受け取り、既に同じものがあればそれを返す。
電波の悪い場所で二度押ししても増えない。

### bootstrap

`pendingStock`（未確定件数）を返却に追加。画面上部の呼び出しに使う。
Basic 5DTU のため、件数のためだけに往復を増やさない。

## フロントエンド

### `lib/geo.ts`

`watchPosition` を薄く包む。**8秒で諦める。** レジ前で待たされるくらいなら位置なしで記録したほうがいい。
許可されなくても、届かなくても、金額の登録は必ず成立する。
有効/無効は `localStorage` に持つ。

### `features/stock/QuickAddSheet.tsx`

**テンキーを画面内に置く。** OS のキーボードを出さないので、

- 開いた瞬間に画面が半分隠れない
- 選択のたびに入力モードへ入らない

という以前の指摘を、自動フォーカスの有無ではなく作りで解決している。

記録後もシートは閉じず「続けて入力できます」と出す。買い回りで複数枚を続けて入れられる。

### `features/stock/StockPage.tsx`

未確定の一覧と確定シート。記録時刻（「今日 12:40」）と位置を手がかりに分類を決める。

- 位置があれば **地図リンク**（座標だけでも見れば思い出せる）
- 推測があれば根拠を表示し、`EntryForm` の初期値に反映
- **場所の名前**を付けられる。次に同じ場所で記録したとき自動で埋まる
- 確定 / 破棄

### 導線

カレンダー最上部に **「⚡ クイック」** を並べ、その下に未確定件数のバナーを出す。
どちらもスクロールなしで届く。
