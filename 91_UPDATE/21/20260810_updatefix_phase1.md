### バックエンド

`11_BE_DEPLOYMENT/src/functions/budgets.ts` を新設。

| エンドポイント | 役割 |
|---|---|
| `GET /api/budgets/{ym}` | 月次サマリー（カテゴリ別 配分・消化・残額、プール残高、締め状態） |
| `PUT /api/budgets/{ym}/initial` | 基本配分の設定。現在の `initial` 合計との**差分のみ**を追記する |
| `POST /api/budgets/{ym}/transfer` | カテゴリ間の組み換え |
| `POST /api/pools/{id}/contribute` | プールへ積む（予算から／臨時で） |
| `POST /api/pools/{id}/draw` | プールから出す（カテゴリへ補填／直接使用） |
| `GET /api/budgets/{ym}/history` | 配分台帳の履歴 |

**予算額は `budget_allocations` の SUM で導出し、UPDATE しない。**
組み換えは `insertAllocationPair()` が ±N の2行を1トランザクションで挿入し、同一 `transfer_group_id` で結ぶ。合計が常に 0 になるため、組み換えを何度行っても総額が狂わない。旧アプリの予算組み換えバグはこの構造で再発しない。

プールとの往復は `movePool()` が担当する。予算由来（`from_budget` / `to_budget`）は配分台帳とプール台帳へ対で記録し、臨時の増減（`external_in` / `external_out`）はプール台帳のみに記録する。**ゼロサム検証は `transfer_group_id` を持つ行にのみ適用する**ため、「何もないところからの積み立て」が不整合にならない。

### 返金の扱いを変更

種別の選択肢を **支出 / 収入 / 振替** の3つに減らした。返金は支出レコードを開いたときに現れる「この支出を返金」から作る。元のカテゴリ・財布・店名を引き継ぎ、日付のみ当日にする。

> 後日の返品や還付で元の支出を消してしまうと、購入した月の支出額が遡って変わってしまう。返金は独立したレコードとして残す。

既存の返金レコードを開いた場合のみ、種別に「返金」が表示され編集できる。

## 修正（軽微修正・計画スキップ）

### 残額不足でも組み換えを実行できるようにした

**症状**: 移動元カテゴリの残額が移動額に満たないと `INSUFFICIENT_BUDGET` で拒否されていた。

**問題**: 赤字の月は予算がマイナスになるのが実態である。この制約では、**組み換えが最も必要な「足りない月」にこそ組み換えできない**という逆転が起きる。

**対処**:

| 箇所 | 変更 |
|---|---|
| `budgetsTransfer` | 残額チェックと `allowOverdraw` フラグを削除 |
| `poolContribute` | 拠出元カテゴリの残額チェックを削除 |
| `remainingOf()` | 参照元が無くなったため削除 |
| `BudgetPage.tsx` | プレビューで移動元がマイナスになる場合に注記を表示 |

マイナスになること自体は変更前後プレビューで確認できるため、実行を止める必要はない。

**プールの残高チェック（`INSUFFICIENT_POOL`）は維持している。** プールは積み立てた実額であり、無い金額を取り出す操作には意味がないため。
