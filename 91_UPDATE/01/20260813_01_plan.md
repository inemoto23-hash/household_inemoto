## 設計の要点

### 1. 予算の残高を口座と同じ組み方にする

口座画面は「**大きな数字 → 区切り線 → 小さな数字を横並び**」で、
手元の額とこれから出ていく額を並べている（`AccountsPage.tsx:326-357`）。予算も同じ形にする。

```
残り
¥15,000                    ← 大きく（32px）
[========------]           ← 消化バー
─────────────────────────
予算        消化        調整
¥20,000    ¥5,000      −¥2,000
```

**母数（予算）と調整を並べて出す。** いまは「調整」が予算の後ろに小さく付くだけで、
`残り = 予算 + 調整 − 消化` という関係が読み取れない。3つを同じ大きさで並べれば式が見える。

金額は `Money`（`.stat-value`）で描く。読み込み中は既に入れた `MoneySkeleton` がそのまま効く。

### 2. 操作をタイルにする

4つちょうどなので **2×2 のタイル**にする。`grid-template-columns: repeat(2, 1fr)`。
狭い画面でも2列を保つ（4つが縦一列に伸びると、下2つがスクロールに隠れる）。

| | |
|---|---|
| ✏️ 残りを設定 | ⇄ 組み換え |
| 🕘 履歴 | 🔒 月を締める |

**面で示す。** `.pick` と同じ「淡いアクセント面＋内側の細い輪」を使い、枠線は引かない。
既存の配色刷新（`20260810_updatefix_design.md`）で決めた方針をそのまま適用する。

**締め済みのときは別の並びにする。** いまも `isClosed` で「履歴 / 締めを戻す」の2つに
変わるので、そのときは2タイルにする。数を無理に4つに揃えない。

**編集中（残りを設定を押した状態）はタイルを出さない。** いまと同じく
「保存 / やめる」に切り替える。操作の途中で他の入口を見せない。

### 3. 設定のタブを並べ替える

`TABS` の並びを **予算 → 口座 → プール → 定期** にする。`value` は変えない
（`?tab=categories` などの既存 URL をそのまま活かす）。

**既定のタブも先頭に合わせる。** いまは `?tab=` が無いと口座が開く（`SettingsPage.tsx:279`）。
並びを変えるのに既定だけ口座のままだと、「並び替えたのに開くのは口座」になる。

### 4. 分析から明細を開けるようにする

#### 明細シートを共有部品にする

明細の一覧は既に**口座**と**予算**の2か所に同じものが書かれている。分析を足すと3か所目になる。
`system_flow.md` が編集シートについて「**3か所に同じものを書くと必ず片方だけ直る**」と
書いているのと同じ話なので、ここで `features/entries/EntryListSheet.tsx` へ切り出す。

中身は「一覧＋行を押すと `EntryEditSheet`」。口座・予算・分析の3画面が同じものを使う。

#### 店舗で絞る道が無い

カテゴリは `GET /api/entries?categoryId=&from=&to=` で足りる（予算画面が既に使っている）。
**店舗で絞る手段が無い。** `entries` の検索は `from` / `to` / `categoryId` / `accountId` / `q` のみ。

場所マスタができたので `placeId` で絞るのが素直だが、**マスタに紐付いていない記録がある**
（一括登録だけの店など）。分析の一覧は `COALESCE(表示名, merchant, place_name)` で束ねているので、
絞り込みも同じ2系統を用意する。

| 一覧の行 | 絞り方 |
|---|---|
| マスタに紐付いている | `?placeId=N` |
| 紐付いていない | `?merchant=名前`（`COALESCE(merchant, place_name)` と突き合わせる） |

そのため `shared/places.ts` の SELECT に **`place_id` を足して返す**（`MAX(pl.id)`）。
FE はそれがあれば `placeId`、無ければ `merchant` で引く。

**BE の変更はこの2つのパラメータ追加だけ。** 集計側の変更は列を1つ増やすのみ。

## 懸念事項・前提条件

1. **明細シートの切り出しが今回いちばん危ない。** 口座と予算で既に動いているものを
   触るので、「振る舞いを変えない」を厳守し、**その工程だけで一度確認する**
2. 店舗の絞り込みは2系統（`placeId` / `merchant`）になる。
   同名で別マスタの店があるとき、`merchant` で引くと**両方混ざる**。
   ただしその状況ではマスタに紐付いているので `placeId` 側が使われる
3. タイルの見た目は好みが割れる。**先に予算画面だけ出して見てもらい**、
   良ければ他の画面にも同じ組み方を広げるのがよい
4. 既定タブを変えると、口座を開く癖のある操作が一手増える
5. `?tab=accounts` の既存ブックマークは動き続ける（`value` を変えないため）
