# プラン: 20260812_04 — 起動スプラッシュと読み込み中の見せ方

## 対象機能・課題

サイトを開いてから数字が出るまでに数秒かかり、その間 **¥0 が本物の数字として描かれる**。
「残高が 0 になった」「予算が消えた」と読めてしまい、バグに見える。

### 遅さの原因は3層に分かれている

| 層 | 内容 | 今回の対象 |
|---|---|---|
| BE 起動 | Function App（Flex Consumption）のコールドスタート | 対象外 |
| DB 接続 | Azure SQL Basic への初回接続 | 対象外 |
| 認証 | MSAL のトークン取得 | 対象外 |

**待ち時間そのものは今回縮めない。** always-ready インスタンスは課金が増えるため、
まず見せ方を直してから判断する（Q&A で合意済み）。

### 「¥0 が見える」のは FE の実装パターン

`data` が未取得のとき `?? 0` / `?? []` で 0 に落としてから描いている。

| 箇所 | 現状 |
|---|---|
| `CalendarPage.tsx:236-248` | `¥{yen(total?.expense ?? 0)}` — 支出・収入・収支の3つ |
| `AccountsPage.tsx:302-317` | `(accounts.data ?? [])` を `reduce` → 合計・支払予定・差し引きが ¥0 |
| `BudgetPage.tsx:341-378` | `total?.remaining ?? 0`、バーの幅、消化・予算・調整 |
| `AnalyticsPage.tsx:379` | `{data ? ... : null}` で守られている。**¥0 は出ない**（文言のみ差し替え） |

同種の `?? 0` / `?? []` は FE 全体で 40 箇所あるが、**¥0 として画面に出るのは上の3画面**。

**出る条件は「`data === undefined`」**なので、正確には次の3つ。

1. 初回アクセス（キャッシュ空）
2. **別の月へ移動したとき**（`queryKey` に月が入るため新規キー扱い）
3. エラー後

上部タブの移動（カレンダー⇄予算⇄口座）は `['bootstrap']` 等が同一キーで共有キャッシュのため、
2回目以降は ¥0 にならず「古い値のまま数秒固まる」挙動になる。

### 起動直後は真っ白

`index.html` は `<div id="root">` だけ。**JS バンドルの取得・評価と MSAL の初期化が
終わるまで何も描かれない**（`main.tsx:41-61` は `handleRedirectPromise` を待ってから render する）。

### 合意済みの前提（Q&A で確定）

1. 方式は **A（スケルトン）+ B（初回スプラッシュ）**。C（前月の値を残す）と D（課金）は今回やらない
2. スプラッシュのモチーフは **既存 BrandMark の波を流す**
3. 読み込み中の金額は **シマー付きブロック**（ダッシュ表示は採らない）

## 実装方針

### スプラッシュは index.html に置く

React コンポーネントとして作ると、**バンドルが落ちて評価されるまで出ない**。
いちばん白い時間に間に合わないので、`index.html` に素のマークアップと
インライン `<style>` を置き、**JS を一切待たずに波が流れ始める**ようにする。

FE 側は消す係だけを持つ（`components/BootSplash.tsx` の `hideBootSplash()`）。

### 消すタイミング

| 状態 | いつ消すか |
|---|---|
| 未認証 | render 直後。サインイン画面を見せる |
| 認証済み | `['bootstrap']` が **解決または失敗**したとき |
| いずれでもない | **8秒の安全弁で必ず消す** |

`bootstrap` はアプリシェル（`AppChrome`）で `useQuery` を張る。既存の
`CalendarPage` / `AccountsPage` と**同じ queryKey なのでリクエストは増えない**。

安全弁を必ず入れる。**スプラッシュに閉じ込められる画面は、真っ白より悪い。**
`main.tsx` の「失敗しても必ず描画する」と同じ考え方（`main.tsx:34-40`）。

- 最低表示 **450ms**（速いときの一瞬のちらつきを消す）
- フェードアウト **220ms**
- 「起動中」の文言は **1.2秒過ぎてから**薄く出す。速いときは何も語らない

### 波の作り

`.brand-mark` と同じ藍のタイル（`--brand-a` → `--brand-b`）の中に、
横長の波形を2本。1周期ぶんを2つ繋げた形を `translateX(-50%)` で流すと**継ぎ目が出ない**。

| | 速度 | 不透明度 |
|---|---|---|
| 上の波 | 2.4s | 1.0 |
| 下の波 | 3.6s | 0.45 |

速度をずらすと2本が離れたり重なったりして、単調なループに見えない。
不透明度は既存 `Brand.tsx` の `opacity="0.45"` をそのまま使い、静止時と同じ絵にする。

`prefers-reduced-motion` は `tokens.css:180-185` の全体ルールが効き、波は静止する。
**止まっても崩れない絵**にしておくこと（静止状態＝現在のロゴと同じ見た目）。

### スケルトン

`components/Skeleton.tsx` を新設する。

```
Skeleton({ w, h, radius })      汎用ブロック
MoneySkeleton({ size })         金額1つぶん。size は Money と同じ値を渡す
```

`.skel` は `--surface-2` の面に `::after` の斜めグラデを 1.4s で横切らせる。
**寸法は実際の金額と揃える。** `.money` は `tabular-nums`（`tokens.css:170-173`）で
桁幅が一定なので、値が入ってもレイアウトが跳ねない。

### 空状態を読み込み中に出さない

`AccountsPage.tsx:367` は `wallets.length === 0` だけで判定しているため、
**読み込み中に「財布がありません」が出る**。`accounts.data` が来てから判定するよう直す。
`StockPage` / `RecurringTab` / `ScheduleBlock` は既に `!isLoading` で守られており、変更不要。

## 検証

```
cd 10_SITE_DEPLOYMENT && npm run typecheck && npm run build
```

画面（`npm run dev` + DevTools のネットワーク絞りで確認）:

1. 回線を Slow 3G にして再読み込み → **白い画面が出ず、波が流れる**
2. キャッシュあり・高速な状態で再読み込み → スプラッシュが**一瞬ちらつかない**（最低450ms）
3. **BE を止めた状態**で開く → 8秒以内にスプラッシュが消え、エラーが読める
4. サインアウト状態で開く → スプラッシュが消えてサインイン画面が出る
5. 口座・カレンダー・予算を初回表示 → **¥0 が一度も出ない**。シマーから直接値へ変わる
6. 月を前後に動かす → 同上（`queryKey` が変わるので初回と同じ経路）
7. 口座が0件の世帯で、読み込み中に「財布がありません」が出ない
8. OS の「視差効果を減らす」を ON → 波が静止し、レイアウトが崩れない
9. ライト / ダーク / OS 追従の3状態でスプラッシュとシマーの色が破綻しない

## 懸念事項・前提条件

1. **スプラッシュに閉じ込めるのが最大の事故。** 安全弁（8秒）と、
   `bootstrap` の **失敗時にも消す**ことを必ず入れる。これが無いと
   「BE が落ちている＝永久にロゴ」になり、原因が一切読めなくなる
2. **`index.html` のインライン CSS はトークンを使えない。** ブランド色は
   リテラルで書くことになるため、`tokens.css` の `--brand-a/-b` を変えたときに
   ずれる。**index.html 側にその旨のコメントを残す**
3. **待ち時間は縮まらない。** 隠しているだけなので、実測でまだ遅ければ
   別途 D（always-ready / `staleTime` 調整）を検討する
4. **タブ移動の「固まる」は残る。** キャッシュがあるときは古い値が表示され続ける。
   これを消すには C（`keepPreviousData` + 更新中の明示）が要るが、今回は対象外
5. スケルトンの寸法が実値とずれるとレイアウトが跳ねる。`Money` と同じ `size` を
   渡す作りにして、**呼び出し側で寸法を書かせない**
